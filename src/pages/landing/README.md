# BADA — 망설임에서, 첫마디로

조사 및 구현: 2026-10-20. 현재 구성은 첫 화면 → 이동형 통화 목업 → 공개 자가진단 → 핵심 질문 3개 → 앱 다운로드다. 서비스 이해와 시작에 필요하지 않은 반복 소개는 제거했다.

## 서비스에서 출발한 콘셉트

BADA의 목적은 통화 전 긴장을 느끼는 사용자가 AI와 안전하게 연습하고 자기 속도로 실제 통화를 준비하도록 돕는 것이다. 서비스에는 시나리오 선택, AI 통화와 스크립트, 기록과 피드백, 자가진단, 워밍업, 커뮤니티가 있다. 랜딩은 상황 선택 → 통화 → 피드백이라는 핵심 이용 흐름에 집중하고 웹 시작 버튼에서 실제 서비스로 연결한다. 진단 효과나 사용자 수·성공률처럼 검증되지 않은 수치는 추가하지 않는다.

하나의 **음성 선**을 공통 모티프로 사용한다. 히어로의 불규칙한 선은 가만히 있어도 작게 꼼지락거리며 스크롤하면 잔잔해지고, 제품 화면의 통화 파형과 연결된다. BADA 그린·기존 Pretendard·검정과 흰색을 유지하며, 큰 크기 대비·비대칭 들여쓰기·얇은 구획선으로 브랜드 편집물의 인상을 만든다.

레퍼런스의 이미지·문구·로고를 제품 에셋으로 복제하지 않았다. 실제 앱 화면은 저장소의 Figma 기반 `AppScreen`과 기존 로컬 에셋을 재사용한다.

히어로는 첫 인사와 음성 파형으로 통화의 시작을 표현한다. `첫마디 건네보기`를 누르면 답장이 나타난다. 이후 `다른 말 건네보기`로 인사·포장 주문·일정·이름 전달 등 8개의 짧은 대화를 차례로 볼 수 있고, 마지막 대화 뒤에는 처음으로 순환한다. 이 미리보기는 마이크·서버·인증을 사용하지 않는다. 음성 파형은 히어로가 화면 밖으로 나가거나 모션 줄이기를 선택하면 멈춘다.

## 현재 구성과 정리 기준

1. **첫 화면:** 브랜드 제목·초록 파형·첫 인사 미리보기와 짧은 웹 시작 버튼을 제공한다. 소개 문구와 스크롤 안내는 제거한다.
2. **한 통의 흐름:** 하나의 기기가 우 → 좌 → 우로 움직이며 통화 전(상황 선택) → 통화 중(스크립트) → 통화 후(피드백)를 설명한다. 각 화면의 해당 영역을 점선 테두리로 짚고, 점선으로 연결된 설명창을 붙인다. 모바일 설명창은 기기 아래에 배치한다. 전체 너비의 하단 바 대신 제목 옆의 작은 단계 선택기를 사용하며, 직접 선택과 방향키·Home·End를 지원한다. 통화 장면에서는 추천 문장·조언·힌트 없이 순서로 도움 방식을 바꿀 수 있으며, 추천 문장을 기본으로 표시한다.
3. **자가진단:** 다섯 문항의 응답 평균을 반올림해 통화 안정형·적응형·긴장형·경계형·회피형을 표시한다. 명칭·설명·레벨 계산은 서버와 일치한다. 결과명 옆 `?` 버튼으로 해당 단계의 설명을 열며, 닫기 버튼·바깥 클릭·Esc로 닫는다. 인증·동의창·서버 요청·답변 저장 없이 동작하며, 로그인 후 `SIGNUP` 자가진단의 서버 연결과 동의 절차는 유지한다.
4. **핵심 질문:** 앱 설치 필요 여부, 실제 전화 연결 여부, 데이터 처리 안내만 남긴다.
5. **팀·서비스 소개:** 팀 소개 내용은 추후 추가하며, 다운로드 앞의 한 화면 높이 섹션에 큰 제목·로고와 팀 GitHub·Instagram 링크만 남긴다. 작은 소개 문구와 서비스 설명은 제거했으며, 오른쪽 구간 내비게이션으로 이동할 수 있다.
6. **다운로드와 푸터:** 두 공식 스토어, GitHub·Instagram, 약관·개인정보·민감정보 안내, 운영 연락처를 제공한다.

감성 문구 전용 화면, 별도 예시 대화, 큰 워밍업 소개, 일상 사진, 커뮤니티 홍보 화면은 핵심 목업과 역할이 겹쳐 제거했다. 반복 시작 버튼·영어 표어·궤적·푸터 워드마크·중복 메뉴도 제거했다. 사용자가 선호한 목업 배경의 01·02·03은 유지한다. 소개 화면을 삭제해도 실제 서비스의 해당 기능과 라우트는 유지한다.

## 구현과 검증 기준

- 낙서 선의 반복 움직임은 초당 30회로 제한한다. 히어로가 화면 밖에 있거나 브라우저 탭이 숨겨지면 멈추고, 모션 줄이기와 라우트 이동에서는 반복 콜백을 제거하고 원래 선을 복원한다.
- GSAP / ScrollTrigger는 랜딩 진입 시 동적 import한다. 브라우저 기본 스크롤을 유지한다. 목업이 이동하는 구간에서 멈춘 경우에만 마지막 스크롤 방향의 완성 장면까지 짧게 이어가며, 읽는 구간과 다른 섹션의 스크롤 위치는 보정하지 않는다.
- `gsap.matchMedia`와 React effect 정리로 모션 선호도 변경·라우트 이동 시 애니메이션을 복원·제거한다. 폰트 로드 후 스크롤 좌표를 갱신한다.
- 모션 줄이기에서는 타이포 진입·히어로 시차·파형 변형·기기 이동과 긴 고정 구간을 제거한다. 세로 모바일·태블릿도 높이 568px 이상이면 고정 무대에서 스크롤에 따라 세 장면을 전환한다. 짧은 화면에서는 일반 흐름의 제품 선택 UI를 제공한다.
- 주요 정보는 애니메이션의 성공 여부와 관계없이 DOM에 남고, 스크린리더용 제목과 버튼 이름을 유지한다. 모양을 위한 복제 문장은 접근성 트리에서 제외한다.
- 색상·타이포·반경은 기존 디자인 시스템을 사용한다. 포스터 크기의 제목도 공유 타이포 토큰을 사용한다.
- 사용자가 제공한 공식 App Store·Google Play 주소를 기본 다운로드 링크로 사용한다. 환경변수로 HTTPS 주소를 재설정할 수 있으며, 별도 설정이 없어도 두 버튼이 동작한다.

## 이동형 목업 레퍼런스 추가

[Heddy](https://www.heddy.site/)를 직접 스크롤하며 기기 프레임과 내부 화면이 장면 사이에서 이어지고, 기록·분석·추천에 맞춰 주변 내용이 변하는 방식을 확인했다. 렌더링된 DOM에서도 `perspective`, `translate3d`, `rotateX`, `rotateZ` 조합과 화면 내부의 이동 요소가 확인된다. 특정 3D 엔진을 사용한다고 단정하지 않고, BADA에서는 기존 GSAP / ScrollTrigger와 CSS 원근 변환으로 구현한다.

폰의 위치와 회전은 시간 반복이 아니라 하나의 스크롤 타임라인에 연결되며, 역방향 스크롤과 창 크기 변경에도 위치를 다시 계산한다. 세로 모바일·태블릿에서는 좌우 이동과 회전 없이 하나의 기기를 고정하고 통화 전·중·후의 화면과 설명을 스크롤로 전환한다. 남는 높이에 맞춰 기기를 축소하고 하단 구간 메뉴의 공간을 예약한다. 탭을 터치하면 같은 스크롤 타임라인의 해당 장면으로 이동한다. 짧은 모바일에서는 설명창을 기기 옆에 배치하고, 높이 568px 미만·모션 줄이기에서는 고정을 정리하고 같은 화면·주석을 직접 선택해 읽을 수 있다.

전환은 전체 타임라인의 24~36%, 64~76%로 짧게 묶고, 설명이 사라지고 다시 나타나는 구간까지 포함한 20~40%, 60~80%에서만 멈춤 보정을 적용한다. 직접 선택은 12%·50%·88%의 안정된 구간으로 이동한다. 모든 장면에서 기기의 세로 중심은 일정하게 유지한다.

스크립트 선택은 장면 사이에도 보존한다. 설명이 이동하며 사라지는 구간에서는 해당 컨트롤에 `inert`를 적용해 보이지 않는 버튼에 초점이 가거나 눌리지 않게 한다. 현재 장면을 반복 선택해도 컨트롤이 잠기지 않는다.

다운로드 링크는 공식 한국어 배지 PNG를 사용하며, 직접 조합했던 로고·텍스트 버튼은 제거했다. 원본 배지의 비율과 여백은 유지하고 호버 시 링크 전체를 1.04배 확대한다. 초록 테두리는 제거하고 키보드 초점에는 검정 외곽선을 제공한다. 모션 줄이기에서는 확대를 생략한다. 출처와 PNG 변환 과정은 `src/shared/assets/landing/README.md`에 기록한다. 상단 로고는 원본 초록색을 표시하고 웹 시작 버튼은 디자인 시스템의 control 반경을 사용한다. 푸터의 임시 팀 소개 버튼은 제거하고 전체 화면 소개 섹션으로 대체했다. 구간 번호의 전체 개수는 내비게이션 데이터에서 계산한다.

랜딩 영역의 글자는 사용자의 요청에 따라 `user-select: none`으로 선택을 막는다. 서비스 화면과 정책 문서에는 적용하지 않는다.

## 랜딩 자가진단

- 기존 API의 공개 문항 조회는 HTTP 200이지만, 결과 제출은 비회원에게 HTTP 401 `인증이 필요합니다`를 반환한다. 유효한 응답이나 사용자 정보를 보내지 않는 빈 본문 요청으로 확인했다.
- 랜딩은 `useLandingDiagnosis`로 로그인 후 자가진단과 분리되어 있다. 기존 랜딩의 별도 3단계 안내를 제거하고, `DiagnosisService.calculateLevel`과 같은 응답 평균 반올림 방식으로 1~5단계를 계산한다. 레벨 명칭·설명은 `CallPhobiaLevel`과 동일하다. 서버가 생성하는 AI 요약을 로컬에서 임의로 만들지 않으며, 레벨 설명은 결과명 옆 `?` 버튼으로 여는 브라우저 기본 팝오버에 표시한다. 팝오버는 페이지 레이아웃을 밀지 않으며 작은 화면에서는 화면 너비에 맞춰 표시한다. 서버 레벨이나 회원 프로필은 변경하지 않는다.
- 기준 소스: [DiagnosisService](https://github.com/ChickenMayoDeopbab/BADA_SPRING_SERVER/blob/3ca8b65f5a9c562e0cf75dd26b14ad555b74518a/src/main/java/ChickenMayoDeopbab/bada/domain/diagnosis/service/DiagnosisService.java), [CallPhobiaLevel](https://github.com/ChickenMayoDeopbab/BADA_SPRING_SERVER/blob/3ca8b65f5a9c562e0cf75dd26b14ad555b74518a/src/main/java/ChickenMayoDeopbab/bada/domain/diagnosis/entity/CallPhobiaLevel.java).
- 시작부터 결과까지 HTTP 요청이나 인증 상태 조회를 하지 않는다. 응답은 컴포넌트 메모리에만 두며 다시 시작하거나 새로고침하면 지운다. 로그인 상태·쿠키·서버의 인증 정책과 무관하게 동작한다.
- 기존 로그인 후 자가진단의 API·동의·결과 처리는 그대로 유지한다.
- 모든 API가 401을 반환하는 환경과 오프라인에서 결과 확인, 이전 응답 유지, 재시작·새로고침 시 초기화를 테스트한다. 실제 서버에는 진단 응답을 제출하지 않는다.
- 주요 소개와 자가진단은 최소 한 화면 높이로 구성한다. 자가진단은 중앙 질문지와 5단계 진행 표시를 사용하고, FAQ는 번호가 있는 간결한 아코디언 목록으로 구성한다. 다운로드는 밝은 배경에 제목과 작은 스토어 배지를 중앙 배치한다. 넓은 화면은 150svh 구간에서 100svh 무대가 잠시 고정된 뒤 푸터로 넘어간다. 모바일 웹은 추가 고정 없이 한 화면으로 제공하고 360px 미만에서는 배지를 세로 배치한다. 모션 줄이기 또는 높이 600px 이하에서도 추가 고정 구간을 제거한다. 스크롤 이벤트를 가로채거나 이동을 강제하지 않는다. 랜딩의 페이지 스크롤바만 CSS로 숨기며 실제 스크롤 동작은 유지한다. 내부 목록과 다른 화면의 스크롤바에는 적용하지 않는다.

## 추가 Figma 링크 검토

사용자가 제공한 23개 링크의 구조와 랜딩 반영 범위는 [figmaReferences.md](./figmaReferences.md)에 기록한다. 현재 랜딩에는 기존 통화 목업의 도움 방식과 자가진단 결과 표시에 필요한 하위 디자인 컨텍스트를 반영한다. 초록색 훈련 설정 미리보기 섹션은 사용자 요청에 따라 제거했다.

자가진단 패널은 최소 높이를 데스크톱 480px·작은 모바일 600px로 유지한다. 문항 제목도 공통 최소 높이를 예약해 문항 길이에 따라 응답 선택과 다음 버튼 위치가 움직이지 않게 한다. 320·390·768·1280px에서 모든 문항과 다섯 가지 결과의 섹션 높이 및 다음 섹션 위치를 확인한다.

## 구간 이동과 자동 오프닝

- Heist의 큰 브랜드 타이포·주인공 이미지·스크롤 장면 전환을 직접 관찰하고, BADA 로고 확대 오프닝과 구간별 마스크 리빌로 재해석했다. 레퍼런스의 이미지나 코드는 복사하지 않는다.
- 오른쪽 레일에서 처음·연습 흐름·자가진단·FAQ·다운로드로 이동하고 현재 위치를 확인한다. 모바일에서는 우측 하단의 카운터를 눌러 메뉴를 펼친다. 기존의 취소 가능한 빠른 스크롤을 재사용한다.
- 첫 로드의 시작 화면에서만 로고가 나타나 확대된다. 같은 앱 세션의 재방문과 직접 해시 이동에서는 반복하지 않으며, 사용자 입력으로 즉시 건너뛸 수 있다. 스크롤·초점을 잠그지 않는다.
- 구간 진입 리빌은 시간 기반으로 끝까지 재생된다. 폼에 초점이 들어오거나 클릭하면 즉시 완료해 입력을 방해하지 않는다. 모션 줄이기에서는 오프닝과 리빌을 건너뛰며 콘텐츠는 기본 DOM 상태로 남는다.
