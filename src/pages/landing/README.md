# BADA — 망설임에서, 첫마디로

조사 및 구현: 2026-10-20. 현재 구성은 첫 화면 → 이동형 통화 목업 → 공개 자가진단 → 핵심 질문 3개 → 앱 다운로드다. 서비스 이해와 시작에 필요하지 않은 반복 소개는 제거했다.

## 서비스에서 출발한 콘셉트

BADA의 목적은 통화 전 긴장을 느끼는 사용자가 AI와 안전하게 연습하고 자기 속도로 실제 통화를 준비하도록 돕는 것이다. 서비스에는 시나리오 선택, AI 통화와 스크립트, 기록과 피드백, 자가진단, 워밍업, 커뮤니티가 있다. 랜딩은 상황 선택 → 통화 → 피드백이라는 핵심 이용 흐름에 집중하고 웹 시작 버튼에서 실제 서비스로 연결한다. 진단 효과나 사용자 수·성공률처럼 검증되지 않은 수치는 추가하지 않는다.

하나의 **음성 선**을 공통 모티프로 사용한다. 히어로의 불규칙한 선은 가만히 있어도 작게 꼼지락거리며 스크롤하면 잔잔해지고, 제품 화면의 통화 파형과 연결된다. BADA 그린·기존 Pretendard·검정과 흰색을 유지하며, 큰 크기 대비·비대칭 들여쓰기·얇은 구획선으로 브랜드 편집물의 인상을 만든다.

레퍼런스의 이미지·문구·로고를 제품 에셋으로 복제하지 않았다. 실제 앱 화면은 저장소의 Figma 기반 `AppScreen`과 기존 로컬 에셋을 재사용한다.

히어로는 첫 인사와 음성 파형으로 통화의 시작을 표현한다. `첫마디 건네보기`를 누르면 답장이 나타난다. 이후 `다른 말 건네보기`로 인사·포장 주문·일정·이름 전달 등 8개의 짧은 대화를 차례로 볼 수 있고, 마지막 대화 뒤에는 처음으로 순환한다. 이 미리보기는 마이크·서버·인증을 사용하지 않는다. 음성 파형은 히어로가 화면 밖으로 나가거나 모션 줄이기를 선택하면 멈춘다.

## 현재 구성과 정리 기준

1. **첫 화면:** 브랜드 제목·초록 파형·첫 인사 미리보기와 짧은 웹 시작 버튼을 제공한다. 소개 문구와 스크롤 안내는 제거한다.
2. **한 통의 흐름:** 하나의 기기가 우 → 좌 → 우로 움직이며 통화 전(상황 선택) → 통화 중(스크립트) → 통화 후(피드백)를 설명한다. 각 화면의 해당 영역을 점선 테두리로 짚고, 점선으로 연결된 설명창을 붙인다. 모바일 설명창은 기기 아래에 배치한다. 전체 너비의 하단 바 대신 제목 옆의 작은 단계 선택기를 사용하며, 직접 선택과 방향키·Home·End를 지원한다. 통화 장면에서는 조언·추천 문장·힌트 없음 상태를 직접 바꿀 수 있다.
3. **랜딩 간단 체크:** 다섯 문항과 응답 평균에 따른 세 가지 안내를 브라우저 안에서 바로 표시한다. 인증·동의창·서버 요청·답변 저장 없이 이용한다. 결과는 Figma의 가운데 정렬 구도·구분선·도움말을 활용한다. 회원 `SIGNUP` 진단의 서버 연결과 동의 절차는 유지한다.
4. **핵심 질문:** 앱 설치 필요 여부, 실제 전화 연결 여부, 데이터 처리 안내만 남긴다.
5. **다운로드와 푸터:** 두 공식 스토어, GitHub·Instagram, 약관·개인정보·민감정보 안내, 운영 연락처를 제공한다.

감성 문구 전용 화면, 별도 예시 대화, 큰 워밍업 소개, 일상 사진, 커뮤니티 홍보 화면은 핵심 목업과 역할이 겹쳐 제거했다. 반복 시작 버튼·영어 표어·궤적·푸터 워드마크·중복 메뉴도 제거했다. 사용자가 선호한 목업 배경의 01·02·03은 유지한다. 소개 화면을 삭제해도 실제 서비스의 해당 기능과 라우트는 유지한다.

## 구현과 검증 기준

- 낙서 선의 반복 움직임은 초당 30회로 제한한다. 히어로가 화면 밖에 있거나 브라우저 탭이 숨겨지면 멈추고, 모션 줄이기와 라우트 이동에서는 반복 콜백을 제거하고 원래 선을 복원한다.
- GSAP / ScrollTrigger는 랜딩 진입 시 동적 import한다. 브라우저 기본 스크롤을 유지한다. 목업이 이동하는 구간에서 멈춘 경우에만 마지막 스크롤 방향의 완성 장면까지 짧게 이어가며, 읽는 구간과 다른 섹션의 스크롤 위치는 보정하지 않는다.
- `gsap.matchMedia`와 React effect 정리로 모션 선호도 변경·라우트 이동 시 애니메이션을 복원·제거한다. 폰트 로드 후 스크롤 좌표를 갱신한다.
- 모션 줄이기에서는 타이포 진입·히어로 시차·파형 변형·기기 이동과 긴 고정 구간을 제거한다. 모바일·짧은 화면에서는 일반 흐름의 제품 선택 UI를 제공한다.
- 주요 정보는 애니메이션의 성공 여부와 관계없이 DOM에 남고, 스크린리더용 제목과 버튼 이름을 유지한다. 모양을 위한 복제 문장은 접근성 트리에서 제외한다.
- 색상·타이포·반경은 기존 디자인 시스템을 사용한다. 포스터 크기의 제목도 공유 타이포 토큰을 사용한다.
- 사용자가 제공한 공식 App Store·Google Play 주소를 기본 다운로드 링크로 사용한다. 환경변수로 HTTPS 주소를 재설정할 수 있으며, 별도 설정이 없어도 두 버튼이 동작한다.

## 이동형 목업 레퍼런스 추가

[Heddy](https://www.heddy.site/)를 직접 스크롤하며 기기 프레임과 내부 화면이 장면 사이에서 이어지고, 기록·분석·추천에 맞춰 주변 내용이 변하는 방식을 확인했다. 렌더링된 DOM에서도 `perspective`, `translate3d`, `rotateX`, `rotateZ` 조합과 화면 내부의 이동 요소가 확인된다. 특정 3D 엔진을 사용한다고 단정하지 않고, BADA에서는 기존 GSAP / ScrollTrigger와 CSS 원근 변환으로 구현한다.

폰의 위치와 회전은 시간 반복이 아니라 하나의 스크롤 타임라인에 연결되며, 역방향 스크롤과 창 크기 변경에도 위치를 다시 계산한다. 모바일·짧은 화면·모션 줄이기에서는 이동과 회전을 정리하고 같은 화면·주석을 직접 선택해 읽을 수 있다.

전환은 전체 타임라인의 24~36%, 64~76%로 짧게 묶고, 설명이 사라지고 다시 나타나는 구간까지 포함한 20~40%, 60~80%에서만 멈춤 보정을 적용한다. 직접 선택은 12%·50%·88%의 안정된 구간으로 이동한다. 모든 장면에서 기기의 세로 중심은 일정하게 유지한다.

스크립트 선택은 장면 사이에도 보존한다. 설명이 이동하며 사라지는 구간에서는 해당 컨트롤에 `inert`를 적용해 보이지 않는 버튼에 초점이 가거나 눌리지 않게 한다. 현재 장면을 반복 선택해도 컨트롤이 잠기지 않는다.

다운로드 링크에는 호버·키보드 초점 반응을 제공하며, Google Play는 공식 스토어 페이지의 원본 컬러 SVG 로고를 사용한다. 출처는 `src/shared/assets/landing/README.md`에 기록한다.

랜딩 영역의 글자는 사용자의 요청에 따라 `user-select: none`으로 선택을 막는다. 서비스 화면과 정책 문서에는 적용하지 않는다.

## 랜딩용 간단 체크

- 기존 API의 공개 문항 조회는 HTTP 200이지만, 결과 제출은 비회원에게 HTTP 401 `인증이 필요합니다`를 반환한다. 유효한 응답이나 사용자 정보를 보내지 않는 빈 본문 요청으로 확인했다.
- 랜딩은 가벼운 체험이라는 사용자 요청에 따라 `useLandingDiagnosis`로 회원 진단과 분리했다. 문항은 기존 LANDING 문항 다섯 개를 로컬에 두고 평균 2.5 미만·3.5 미만·그 이상으로 통화 부담 안내를 나눈다. 서버 레벨이나 회원 프로필을 변경하지 않는다.
- 시작부터 결과까지 HTTP 요청이나 인증 상태 조회를 하지 않는다. 응답은 컴포넌트 메모리에만 두며 다시 시작하거나 새로고침하면 지운다. 로그인 상태·쿠키·서버의 인증 정책과 무관하게 동작한다.
- 기존 회원 진단의 API·동의·결과 처리는 그대로 유지한다.
- 모든 API가 401을 반환하는 환경과 오프라인에서 결과 확인, 이전 응답 유지, 재시작·새로고침 시 초기화를 테스트한다. 실제 서버에는 진단 응답을 제출하지 않는다.
- 주요 소개와 자가진단은 최소 한 화면 높이로 구성한다. 자가진단은 중앙 질문지와 5단계 진행 표시를 사용하고, FAQ는 번호가 있는 간결한 아코디언 목록으로 구성한다. 다운로드는 큰 제목·브랜드 로고·스토어 버튼으로 한 화면을 채우며, 기본 180svh 구간에서 100svh 무대가 잠시 고정된 뒤 푸터로 넘어간다. 모바일은 160svh이며 모션 줄이기 또는 높이 600px 이하에서는 추가 고정 구간을 제거한다. 스크롤 이벤트를 가로채거나 이동을 강제하지 않는다. 랜딩의 페이지 스크롤바만 CSS로 숨기며 실제 스크롤 동작은 유지한다. 내부 목록과 다른 화면의 스크롤바에는 적용하지 않는다.

## 추가 Figma 링크 검토

사용자가 제공한 23개 링크의 구조와 랜딩 반영 범위는 [figmaReferences.md](./figmaReferences.md)에 기록한다. 현재 랜딩에는 기존 통화 목업의 도움 방식과 자가진단 결과 표시에 필요한 하위 디자인 컨텍스트를 반영한다. 초록색 훈련 설정 미리보기 섹션은 사용자 요청에 따라 제거했다.

자가진단 패널은 최소 높이를 데스크톱 480px·작은 모바일 560px로 유지한다. 문항 제목도 공통 최소 높이를 예약해 문항 길이에 따라 응답 선택과 다음 버튼 위치가 움직이지 않게 한다. 320·390·768·1280px에서 모든 문항과 세 가지 결과의 섹션 높이 및 다음 섹션 위치를 확인한다.
